# جدول حالات الاختبار التفصيلية لشاشات الرعاية السريرية للمريض الداخلي (Inpatient Clinical Care Test Cases)

تغطي هذه الوثيقة حالات الاختبار الوظيفية (Functional)، السلبية (Negative)، واختبارات الحواف (Boundary Values) لكافة تابات شاشة **إضافة خدمات لمريض** (`/waiting-list/patient-services` والتابات التابعة لها):
1. **خدمات المريض** (`patient-services`)
2. **الأشعة** (`patient-rays`)
3. **التحاليل** (`patient-tests`)
4. **صرف أدوية ومستلزمات** (`charge-patient-med`)
5. **طلب أدوية ومستلزمات** (`patient-request-med`)
6. **مرتجع الأدوية** (`patient-return-med`)
7. **بنك الدم** (`patient-blood`)
8. **الأجهزة الداخلية** (`patient-internal-devices`)
9. **أجهزة شركات خارجية** (`patient-external-devices`)
10. **النظام الغذائي** (`patient-diet`)

## خطة إعادة الاختبار بمجرد حل مشكلة الـ Context (Re-test Plan):
بمجرد قيام فريق التطوير (Backend Team) بحل الـ Scoped DbContext واستخدام Context منفصل لكل استعلام متزامن:
1. تشغيل سويت الاختبارات الشامل:
   ```powershell
   $env:PYTHONPATH="."; pytest tests_ui/test_ui_inpatient_clinical_care.py -v -s
   ```
2. تشغيل سويت الاختبارات السلبية:
   ```powershell
   $env:PYTHONPATH="."; pytest tests_ui/test_ui_inpatient_clinical_negative.py -v -s --html=report_clinical_negative.html --self-contained-html
   ```
3. التحقق من تحول الـ Toasts من رسائل تقنية خام إلى رسائل ودية للمستخدم مثل: `"برجاء اختيار الخدمة"`.
